# Crude Outlook: Crude Oil Price Prediction System

A beginner-friendly, end-to-end machine learning project that forecasts **WTI** and **Brent** crude oil prices for the next 7 trading days, publishes them to a live website, and updates itself every weekday.

**Live site:** _add your Vercel URL here after deploying (see [Deploy your own](#deploy-your-own))_

What makes this project useful for learning is that it's **honest**: the website shows how accurate the model really is, compared with the simplest possible guess ("tomorrow's price = today's price").

---

## What it does

1. **Downloads** 5 years of daily market data from Yahoo Finance: oil futures plus natural gas, the US dollar, the S&P 500, the VIX and 10-year Treasury yields. It needs no API key.
2. **Builds features** such as recent returns, volatility, RSI, MACD, moving averages and the Brent–WTI spread.
3. **Trains three models** (Ridge regression, XGBoost, LightGBM) for each horizon from 1 to 7 days ahead.
4. **Tests them** on the most recent ~6 months of data, which the models never saw during training.
5. **Writes** everything to `web/data/forecast.json`.
6. **Publishes** it on a static website hosted on Vercel.
7. **Repeats daily**: a GitHub Action reruns steps 1–5 every weekday evening and commits the new forecast, and Vercel redeploys automatically.

```
 Yahoo Finance ─┐
 EIA (optional) ├─► crudeoil_prod/app.py ─► web/data/forecast.json ─► website on Vercel
 FRED (optional)┘        ▲                          │
                         └──── GitHub Action (every weekday) commits ─┘
```

## A note on accuracy (read this!)

Oil prices behave close to a **random walk**: day-to-day moves are mostly noise. Even professional models struggle to beat "no change" by much. In this project:

- Big, flexible models (deep trees, LSTMs) **memorized noise** and did clearly *worse* than "no change" on the test period.
- So the final models are small and heavily regularized, and their average is **shrunk toward "no change"** by a factor (0 to 1) learned from validation data.
- The result is roughly as accurate as "no change", sometimes slightly better and sometimes slightly worse. The website shows the exact numbers.

That's a real, useful lesson. If a price-prediction tutorial claims 95% accuracy, it's usually measuring something that doesn't matter or leaking future data into training.

## Quick start (run it on your computer)

You need **Python 3.10+** and **git**.

```bash
# 1. Get the code
git clone https://github.com/rahulkhanna5/crude-oil-price-prediction-system.git
cd crude-oil-price-prediction-system

# 2. Create a virtual environment (keeps packages separate from your system Python)
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 3. Install dependencies
pip install -r crudeoil_prod/requirements.txt

# 4. Run the pipeline (takes about 15-30 seconds)
python crudeoil_prod/app.py

# 5. View the website
python3 -m http.server 8000 --directory web
```

Then open <http://localhost:8000> in your browser.

The pipeline prints one line per forecast horizon, for example:

```
[WTI] h=1: forecast $89.60 | test MAE $2.55 vs naive $2.52 | direction 51%
```

- **h=1**: forecasting 1 trading day ahead
- **test MAE**: on average, how many dollars the forecast missed by on the test days
- **naive**: the same measure for the "no change" guess (lower is better)
- **direction**: how often it correctly predicted up vs. down

> Tip: you can't open `web/index.html` by double-clicking it, because browsers block loading `forecast.json` from `file://` pages. Use the `http.server` command above.

## Optional API keys

The project works without any keys. To add extra features:

1. Copy `crudeoil_prod/.env.example` to `crudeoil_prod/.env`.
2. Fill in the keys you have:
   - `EIA_API_KEY`: free at <https://www.eia.gov/opendata/register.php> (adds weekly US crude inventories)
   - `FRED_API_KEY`: free at <https://fred.stlouisfed.org/docs/api/api_key.html> (adds inflation expectations and the yield curve)
3. Run `python crudeoil_prod/app.py` again.

`.env` is listed in `.gitignore`, so your keys never get committed. **Never paste API keys directly into code.**

## How the model works

**Target.** Instead of predicting the price itself ($89.61), we predict the *percentage change* (technically the log return). Changes look statistically similar across years, while price levels drift to values the model may never have seen.

**Time-based split.** Data is never shuffled. The oldest 70% is used for training, the next 15% for validation and the most recent 15% for testing:

```
|------------ train 70% ------------|-- validation 15% --|-- test 15% --|
                                                            ↑ scores shown on the website
```

A small gap separates each part so a 7-day target can't overlap the next part.

**Models.** For each horizon (1–7 days) we train:

| Model | What it is |
|---|---|
| Ridge regression | A linear model with a penalty that keeps coefficients small |
| XGBoost | Many shallow decision trees, each fixing the errors of the last |
| LightGBM | A faster variant of the same idea |

Their predictions are averaged, then multiplied by a **trust factor** between 0 and 1, fitted on the validation data. A trust factor of 0 means "just predict no change".

**Likely range.** The shaded band on the chart comes from the model's actual errors on the test period: 8 out of 10 test days landed inside it.

**Final forecast.** After testing, the models are retrained on *all* the data and used to forecast from today's close.

## Deploy your own

The website is static files, so hosting on Vercel is free and needs no server.

### 1. Put the code on GitHub
Fork this repo, or push your copy to your own GitHub repository.

### 2. Connect it to Vercel
1. Sign in at <https://vercel.com> with your GitHub account.
2. Click **Add New… → Project** and import the repository.
3. Leave the settings as they are; `vercel.json` already tells Vercel to serve the `web/` folder.
4. Click **Deploy**. You'll get a URL like `https://your-project.vercel.app`.

Or from a terminal: `npm i -g vercel && vercel --prod`.

### 3. Turn on daily updates
The workflow in `.github/workflows/daily-forecast.yml` runs every weekday at 22:30 UTC, after US oil futures settle.

1. On GitHub, open your repo's **Actions** tab and enable workflows if asked.
2. Go to **Settings → Actions → General → Workflow permissions** and select **Read and write permissions** so the Action can commit the new forecast.
3. (Optional) Add `EIA_API_KEY` / `FRED_API_KEY` under **Settings → Secrets and variables → Actions**.
4. To test it right away: **Actions → Daily forecast → Run workflow**.

Each run commits a new `forecast.json`, and Vercel redeploys the site within a minute.

## Ideas for extending it

- Add news sentiment as a feature (the notebook has a NewsAPI + VADER version).
- Try walk-forward (rolling) evaluation instead of a single test period.
- Forecast other commodities: gasoline (`RB=F`), heating oil (`HO=F`) or natural gas (`NG=F`).
- Track the live forecasts over time and score them after the fact.
- Compare against the LSTM in `crudeoil.ipynb` using the same test period.

## Troubleshooting

| Problem | Fix |
|---|---|
| `ModuleNotFoundError` | Activate the virtual environment and rerun `pip install -r crudeoil_prod/requirements.txt` |
| `Yahoo Finance returned no data` | Check your internet connection. Yahoo sometimes rate-limits, so wait a minute and retry |
| Website says "Couldn't load data/forecast.json" | Run `python crudeoil_prod/app.py` first, and serve with `python3 -m http.server` (don't double-click the HTML file) |
| GitHub Action fails on `git push` | Set workflow permissions to "Read and write" (Deploy step 3) |
